Arithmetical operations are performed by order of precedence, just like in normal mathematics. From highest to lowest precedence:
- Grouping with parentheses (`(` and `)`); just like in real math, you can modify the precedence ordering by wrapping parentheses around things
- Calling `floor`/`round`/`ceil`/`abs`
- Exponentiation (`**`)
- Multiplication (`*`), division (`/`), and modulus (`%`), in the order they appear (left-to-right) in the formula
- Addition (`+`) and subtraction (`-`), in the order they appear (left-to-right) in the formula

Library is primarily a dice engine and has its own order of operation. Nonetheless the dice engine supports basic math and functions such as `floor()` and ceil(). This means that putting parentheses inside of your dice formula will not always affect the outcome of the roll. Here is the general order of operations:

- Roll queries are executed up to 99 levels deep (the player making the roll is asked to provide a value for each query, and that value is substituted in where the roll query appears in the formula).
- Inline rolls are executed, starting with the most deeply nested inline roll working upward. The overall result of the inline roll is substituted in place where it appeared in the formula.
- The remaining roll is executed: first, dice are rolled for any dice (e.g. "2d6" is rolled; including any special dice such as dropped or exploding), then the result of that roll is substituted into the formula. Next, `floor()` and `ceil()` functions are executed.
- Finally, the entire remaining formula is evaluated, including observing proper math order of operations (parentheses first, then multiplication/division, then addition/subtraction).



For expression evaluation we need support of multiple separate steps:

1 parse step - `parse`
 - accepts text to parse
 - generates AST for provided text
 - returns AST, so we can keep it for later

Then, depending on what plugins we are using currently:

A extract roll queries list - `extractQueries` (see `Roll Queries`)
 - accepts AST from (1)
 - returns list of schemas, describing format of required user input 

B extract tables list - `extractTables` (see `Table Rolls`)
 - accepts AST from (1)
 - returns list of referenced table names

C extract rolls - `extractRolls` (see `Roll History References`)
 - accepts AST from (1)
 - returns list of referenced rolls result ids

2 Now we can
 (a) get map of tables by table name { `table name`: table_rows_array }
 (b) get map of rolls by roll id { `roll id`: roll_value }
 (c) build a form for user data input and wait for user to fill form and send it back to us. user input should be validated against schemas `extractQueries`

3 finaly get result - `evaluate` we can proceed with evaluation
 - access data, required by used plugins:
  - accepts (2.a)
  - accepts (2.b)
  - accepts user provided data (2.c)
 - expand roll queries with user provided data
 - evaluates all expressions
 - returns final result of evaluation
