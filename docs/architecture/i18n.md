# Internationalization (i18n)

## Setup

`src/i18n/index.ts` creates a Vue I18n instance:

```ts
createI18n({
  legacy: false,
  locale: 'ru',
  fallbackLocale: 'en',
  messages: { en, ru },
});
```

- `legacy: false` means Composition API mode; components call `useI18n()`.
- Messages are plain nested JSON files: `src/i18n/locales/en.json` and
  `ru.json`.
- Locale starts as Russian, then `main.ts` applies `configStore.savedLanguage`
  (default `navigator.language`) immediately via a watcher.
- Quasar's locale is synchronized with the app locale (`main.ts` calls
  `Quasar.lang.set` when `savedLanguage` changes).

## Language persistence

`LanguageSwitcher.vue` is rendered inside `SettingsDialog.vue`, which opens from
the left navigation’s Settings item. It normalizes the active locale to the
supported `en`/`ru` values and persists the selection to
`configStore.savedLanguage` (`localStorage` key
`dmh-config:savedLanguage`). Browser locales such as `en-US` display as
`English` rather than an unmatched raw tag.

## Key structure

Top-level namespaces in `en.json`/`ru.json`:

```
app, navigation, home, notes, parties, pawns, characters, encounters,
common, validation, notFound, project, statCard, combat,
encounterCard, partyView, playlist, noteTypeSelector,
editor, partySelector, language, tags, backup,
markdownEditor, mentions, modal, characterEditor, tagSelector, timers,
pwa, calculator, jukebox, ambientSoundPage
```

The two locales have identical key sets, which is a good
sign. Values can still be stale relative to the UI.

### Dynamic key patterns

- `t('nav.' + key)`, `t('statCard.' + item.key)`,
  `t('encounters.combats.status.' + status)`.
- `t(placeholder)` where the caller passes a key such as
  `'characters.fields.name'`.
- Component props often carry translation keys rather than text
  (`ViewHeader.buttons[].title`, `BaseListView.createTitle`,
  `MentionInsertPopup`).

Because keys are dynamic, static extraction cannot prove coverage. A key
The missing keys (`partyView.title`, `noteTypeSelector.iconPlaceholder`,
`common.linked`) and the `t('common.')` delete-key typos were fixed during
remediation.

## Adding a locale

1. Add `src/i18n/locales/<code>.json` with the same key tree.
2. Import it in `src/i18n/index.ts` and add it to `messages`.
3. Add an option in `LanguageSwitcher.vue`.
4. Quasar's language/icon set follows the selected locale (`main.ts` calls
   `Quasar.lang.set`).
5. Add a CI check comparing key sets (proposed in
   `proposals/technical-proposals.md`).

## Translation conventions in this project

- Strings use `{name}` interpolation, e.g.
  `confirmDelete: "Delete \"{title}\"?"`.
- Some components translate only once at setup; those strings do not update on
  locale change unless the component recomputes (most use `t()` in templates,
  so they do).
- English text is embedded directly in some templates (CombatView phase labels
  "Preparation", "Active", "Ended"). These are not translated.

## Known issues

- English-only literal strings remain in combat/document views.
- `configStore`'s `getValue` parses `localStorage` without guarding malformed
  JSON; a corrupt value prevents the config store from constructing.
- `useI18n()` is called inside `useTimerStore`'s setup. This works when the
  store is created after the i18n plugin is installed (as in `App.vue`) but
  fails in unit tests or any code that instantiates the store before i18n.
